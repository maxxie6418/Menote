## 一、需求 ① 编辑界面的属性样式优化，统一 YAML 格式与显示样式

**用户原话**：编辑界面的属性样式优化，需要统一 yaml 格式和显示样式。

**我理解到的**：正文顶部那条属性区（front matter 呈现）现在只做到「能看能改」，还没做到「口径统一 + 长得一致」。要分两层处理——**写入口径**（YAML 怎么生成）与**显示样式**（属性区怎么排）。

**已核实的现状**（记录于 2026-10-04）：

| 已有 | 位置 |
|---|---|
| front matter 保真读写（外来键按原格式写回，不引通用 YAML 库） | `packages/mdcore/src/frontmatter.ts`；`readForeignKeys` / `writeForeignKey` / `removeForeignKey` |
| 外来 front matter 与表格键的边界拆分（`preservedLines` / `foreignLines`） | v0.8.10 已收口 |
| 属性卡片（标题之下、正文之上的第三条带，可折叠） | v0.8.11 落地，设计 `docs/modules/MeNote-笔记属性卡片-设计-v1.md` v1 |
| 表格的 YAML 列定义（`columns` / `views` / `row_id_column`，嵌在 `menote:` 下） | M4 落地 |

**必须先问清的口径**（我不擅自定）：

1. **「属性」指哪一块？** 笔记 front matter（属性卡片）／表格列定义 YAML／两者都要。
2. **「统一 YAML 格式」统一的是哪一层？**
   - 序列化口径（引号、空值、数组写法、缩进、键序）——但**外来属性一根不动**是已定稿口径，"统一"不能顺手动它；
   - 还是 MeNote 自有键（`title` / `tags` / `menote.*`）的书写规范统一。
3. **「显示样式」统一到哪一级？** 属性区内部（行距、标签列宽、键值对齐、只读态）；还是与标题带、正文区的**宽度与留白**对齐（v0.8.15 已把宽度对齐过一次，需确认是否还有别的没对齐）。
4. 外来键与 MeNote 键在显示上要不要**视觉分层**（现在同一个 `chip` 形态，标准键和外来键分不出来）。

**硬约束**：`frontmatter.ts` 文件头「不做通用 YAML」不动；键名不翻译；不引 YAML 依赖（属「加生产依赖」，须确认）。

## 二、需求 ② 文章相关菜单重新设计（左侧功能栏 + 右上角更多菜单）

**用户原话**：文章相关的菜单要重新设计，包括左侧功能栏里的和右上角的更多菜单。

**我理解到的**：两处入口现在各自堆了一批与"文章"有关的动作，重复或难找，要重新规划信息架构。

**待定口径**：

1. 两处各自**现在到底有哪些项**、重复的是哪几条——需逐屏枚举后列清单给用户看，再谈重排（不凭印象）。
2. 重排的目标形态：分「常用 / 危险」？还是按「作用于当前文章 / 作用于全局」分？破坏性动作（永久删除、清空回收站）放哪。
3. 移动端呈现未定稿（`DESIGN.md` §2.4），本条**不得顺手发明移动端形态**，只按桌面稿做且不留下仅桌面成立的写法。

**硬约束**：导航结构属 `AGENTS.md`「先确认再动」里的**全局视觉 / 导航结构**，且视觉源只有 `DESIGN.md` 一份——先稿后码。

## 三、需求 ③ 设置中新增样式编辑（如不同层级标题栏加粗或改色）

**用户原话**：需要在设置中新增一些样式的编辑，比如不同层级的标题栏加粗或改色。

**我理解到的**：让用户能调正文标题各层级的呈现（字重、颜色，可能还有字号/间距），而不必改 CSS 主题。

**待定口径**：

1. **可配置的粒度**：H1–H4 逐级？还是「标题」一类？正文 / 表格 / 属性区 / 笔记列表是否共用一套？
2. **允许改哪些属性**：字重、颜色、字号、上下间距、是否可去掉下划线？建议收窄，但收窄到哪要用户定。
3. **作用域**：跟随账号（多端一致）还是仅本机？——v0.8.4 已给每个设置项加 `.scope-tag`（`本机` / `跟随账号`），新项必须归到其中一侧，且理由要说清（例如换设备就该跟着走 vs 主题跟随设备）。
4. **落法**：CSS 变量注入 / 挂到现有主题机制 / 走新的用户偏好字段——**这属于「公共类型 / 全局配置」改动，须确认**。还要确认它对**分享视图**与**只读预览**是否生效。
5. 是否给**预设**（如"清爽 / 高对比"）还是纯逐项微调；改完是否即时预览、是否要"恢复默认"。

**与需求 ① 的关系**：①定统一后的层级样式语义，③是把它开放给用户改——所以 ③ 应在 ① 之后。

## 四、需求 ④ 编辑器主页要有样式工具栏

**用户原话**：编辑器主页要有样式工具栏。

**我理解到的**：正文编辑界面要有可见的格式工具栏，不必每次打 `/`。

**已核实的现状**（记录于 2026-10-04）：

- 现有格式入口只有**斜杠命令** `/`，命令源在 `apps/web/src/app/editor/format-commands.ts`，基础集＝**加粗 / 斜体 / 无序 / 有序 / 引用 / 行内代码 / 链接**，另按宿主追加**任务清单**（Memo / 待办有，笔记快捷录入首期不给）；`/图片`、`/附件` 仍未接入正文。
- 设计与来源：`docs/modules/Menote-编辑拓展-设计-v3.md` v3.4 §三-2（**该文档已定"快捷输入只承担基础集、正文承担完整写作能力"**）；`/图片``/附件` 登记在 `docs/todo/Menote-开发计划-v1.md` 遗留表。
- 正文三档：**仅编辑 / 仅预览 / 即时渲染**（双栏已移除）。

**待定口径**：

1. **常驻还是选中时浮出**（浮出更省地方，但触屏没有 hover／选区概念不同）。
2. **按钮集**：是否就是 `/` 那套命令（共用 `format-commands.ts` 一个源），还是补齐表格 / 图片 / 附件。
3. **在哪些档出现**：「仅编辑」和「即时渲染」都出？「仅预览」只读不出？
4. 有无状态高亮（当前选区是否已是加粗）、有无下拉（如标题 1–4）。
5. 触屏命中区（`DESIGN.md` §2.4 底线：不以悬停为唯一入口）。

**硬约束**：不得另起视觉语言——按钮用 `DESIGN.md` 指定的既有组件拼；工具栏里的每个动作都要落到同一份命令源，不能与 `/` 各写一套。

## 五、四条之间的关系与建议顺序

| 需求 | 依赖 | 说明 |
|---|---|---|
| ① 属性样式 / YAML 统一 | 无 | 其它三条都建立在"层级与属性呈现口径统一"之上 |
| ④ 样式工具栏 | ①（弱） | 工具栏的按钮集取决于层级样式口径是否已统一；命令源本身已存在 |
| ③ 设置里的样式编辑 | ①（强） | 开放可配置的前提是先有一套统一的默认样式 |
| ② 菜单重设计 | 无（但同属编辑界面信息架构） | 独立可先做；若与 ③④ 同批做，界面改动面会很大 |

**建议顺序（待用户拍板）**：① → ④ → ③ → ②。把风险最大、最需要先定口径的放在前面；② 信息架构最独立，若用户想先看到变化也可以提前。
