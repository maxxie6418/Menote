## 一、为什么还要再动一次（现状问题，逐条带落点）

首页在 v0.7.1 已按原型重做过一次（`docs/modules/Menote-M7-首页重做-界面稿-v1.md`）。**那轮改的是「三块等分 → 一主两副」的结构配重，落地后仍留四个问题**——本轮就是收它们。

| # | 问题 | 落点与证据 |
|---|---|---|
| 1 | **宽屏下内容被拉满整屏**。`DESIGN.md` §2.3 明写「首页卡片组 920px 上限」，但 `.home__scroll`（`app.css:5146`）**没有 `max-width`**；同类的 Memo 有 740（`app.css:1873`）、待办有 920（`app.css:2653`）、设置页有 790（`app.css:4531`）。**唯独首页漏配，且无用例断言** | `app/theme/app.css:5146` |
| 2 | **焦点卡没有焦点**。今日待办号称主卡，但与最近动态、统计三者都是同款 `.home-card`（1px 边框 + radius + panel 底），只靠 `flex: 1.15` 区分——用户反馈「看不出主次」 | `app/theme/app.css:5279` |
| 3 | **块太多**。四个区（甲板 / 动作带 / 导航三组）都带边框外壳，像卡片墙；其中「条目统计」只是三个数字，却独占一个带壳的区块（标题 + 数字 + padding） | `app.css:5195`（`.home-band`） |
| 4 | **动作与位置同形**。「快捷方式」与「快速导航」都是「微标标题 + 横排小按钮」，动作带还多一层带边框的壳，两者混在一起分不清语义；另：页头那行副标题「概括预览 · 快捷方式 · 快速导航 · 全部由本地元数据计算」是**开发口吻**，按 `DESIGN.md` §5.4 应收进 `InfoHint` | `app.css:5232`、`.pane-head .sub` |

**共同根因**：把「三个回顾性数字 + 两条列表」当成了四块同级的卡片来摆。首页真正要做的是**让人一眼看到今天要做什么**，其余是出口。

## 二、目标结构

```text
┌ 首页  ⓘ ───────────────────────────  笔记 12 · 表格 3 · Memo 48 ──┐ ← 页头一行（概览带＝读数）
├─────────────────────────────────┬───────────────────────────────┤
│ ┃ 今日待办      来自清单 Memo  打开待办视图→   ← 焦点卡（左）      │
│ ┃  ● 交电费          今天                                   │ │ ← 右：最近动态
│ ┃  ● 回邮件          明天                                   │ │   （无边框，只一条顶线）
│ ┃                                                  另有 4 条 Memo │ │
├─────────────────────────────────┴───────────────────────────────┤
│ ─────────────────── 1px 分隔线 ──────────────────────────────── │
│ 快捷方式                                                              │
│ [+ 新建笔记] [🕐 记录 Memo] [☑ 新建待办] [🔒 打开加密空间] [🔍 搜索]      │ ← 裸行，无外壳
├────────────────────────────────────────────────────────────────┤
│ 文件夹    [chip] [chip]                                            │
│ 标签      [chip] [chip]                                            │ ← 快速导航三组
│ 常用视图  [chip] [chip] [chip] [chip] [chip] [chip]                  │
└────────────────────────────────────────────────────────────────┘
        整块内容居中，两侧留白（920px 上限，居中）
```

四段节奏：**页头读数（一行）→ 中部两栏（一主一副）→ 动作裸行 → 导航三组**。段与段之间用 `--sp-5` + 一条 `1px` 分隔线，不靠卡片边框分层。

## 三、四条视觉规则

### 规则 1：宽度上限（补真缺陷）

- 新增 `.home__body`：`max-width: 920px; margin: 0 auto`，在 `.home__scroll`（滚动容器，`overflow-y: auto`）**之内**。
- **照待办页的既有做法**（`app.css:2653` 的 `--task-cap`）：限的是**内容容器**，不是滚动容器。滚动容器保持满宽，滚动条仍在工作区右缘。
- 甲板、动作带、导航三组都在 `.home__body` 里，所以**一次收口**，不必给每块各写一遍。
- **补一条回归断言**：`layout-invariants.test.ts` 加「首页内容有 920px 上限且居中」，否则下一次改版又会漏。

### 规则 2：主次（焦点卡真给焦点）

今日待办与最近动态**不再是同级**——这正是 `DESIGN.md` §4.1-3「相同层级的元素间距必须相同」的反面用法：**不同层级可以有不同内边距**。

| | 今日待办（主） | 最近动态（副） |
|---|---|---|
| 外壳 | `.home-card` + 变体 `lead` | `.home-card` + 变体 `flat` |
| 边框 | 保留 `1px` 描边 + **左侧 2px 主色强调线** | **去掉描边与底色**，只留一条顶部 `1px` 分隔线 |
| 内边距 | `--sp-4`（比常规档松一档，把主次做进留白） | `--sp-3`（常规档） |
| 标题 | `fs-small` 保持，但配 Icon；行内元信息（日期/优先级）照旧 | 同 |

- 2px 左侧强调线**不是新发明**：`.markdown-body blockquote`（`app.css:1019`）与 CodeMirror 光标都是同一写法，语义一致（画一条线标出「这是主线」）。它配了标题、留白与更宽的行，**不违反禁止项 #4**（不是用颜色单独表达状态）。
- **不新增实心主色按钮**（`DESIGN.md` §5.1 / 禁止项 #6）：焦点靠留白与线条，行动出口「打开待办视图」仍是弱操作（`.home-card__link`）。

### 规则 3：卡片降一档（解「卡片墙」）

| 块 | 原来 | 改后 |
|---|---|---|
| 条目统计 | 带边框的 `.home-band` 独立区块 + 「条目统计」标题行 | **并入页头右侧**做读数：无边框无底色，「条目统计」四字**取消**，口径留在 `ⓘ`（`InfoHint` 现成文案不动） |
| 最近动态 | 带边框卡片 | 变体 `flat`（见规则 2） |
| 今日待办 | 带边框卡片 | 保留（唯一一个带框的块） |
| 快捷方式 | 带边框的 `.home-acts-bar` | **裸行**：去边框去底色，只留微标标题 + 按钮行 |

结果：整屏**从 4 个带框块降到 1 个**（今日待办），其余靠留白与分隔线分层。

- **实时计数不收进 `InfoHint`**（禁止项 #8）：三个数字**保持可见**，`ⓘ` 里只放「口径 / 来源」这类说明性文字（`StatBand` 现有那段文案照搬）。
- 锁定时那句「数字不区分锁定状态」跟着进页头读数区，仍是**可见微字**，不塞 `ⓘ`。

### 规则 4：动作与位置分家

| | 快捷方式（做什么） | 快速导航（去哪里） |
|---|---|---|
| 标题 | 「快捷方式」微标 | 「文件夹 / 标签 / 常用视图」三组微标 |
| 控件 | `.home-act` 描边按钮（28px） | `Chip` 胶囊（21px） |
| 外壳 | **去掉**带边框的壳 | 本来就没有壳 |
| 与上一段的边界 | 上方一条 `1px` 分隔线 + `--sp-5` | 组间 `--sp-3`（现状） |

改后两者唯一的共同点是「微标 + 横排」，但**控件形态不同 + 有无外壳不同**，语义（动作 / 位置）一眼可分。
