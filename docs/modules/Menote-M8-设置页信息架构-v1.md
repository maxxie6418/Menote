## 一、为什么要动

对设置页做产品评估后的结论：**分类骨架本身站得住，问题在粒度不均与边界模糊。**

- **粒度差两个数量级**：`PrivacySettingsPage` 381 行 5 张卡，「编辑器」整页只有 3 个开关（30 行有效内容），「关于」只有版本号 + 一个链接。11 个**等权重**的导航项，实际体量差异巨大。
- **两组语义重叠**：「备份与导出」与「数据管理」都在回答"数据怎么出去、怎么回来、怎么腾地方"，且两者共享的决策高度耦合（备份体积直接由附件占用决定），却隔着两个平级分类；「账户与安全」与「隐私锁」都是密码与门禁，顶栏入口是同一个，出口却分两页。
- **作用域不透明**：「通用」同时装了设备级偏好（主题）和账号级偏好（时区、启动视图…），区别**只写在 ⓘ 悬停里**，页面上没有任何标识。用户无从预期"为什么这台设备改了另一台没改"——这是本次最实质的缺陷。
- **两处过期文案**：「已登录设备」「成员账户管理」都写着"将在后续里程碑提供"，而它们指向的 M6 已于 v0.7.0 收口。

**不动的部分**：设置项本身的行为、契约（`packages/shared/src/settings.ts`）、接口、存储、作用域语义、以及"一次只渲染一个分类"的两栏分页骨架（`DESIGN.md` §2.7 已定稿）。

## 二、调整方案

### 2.1 分类清单：11 → 9

| 原分类 | 处置 | 去向 |
|---|---|---|
| 通用 | 保留 | 吸收「编辑器」全部内容 +「关于」全部内容 |
| 账户与安全 | 保留 | — |
| **编辑器** | **撤销** | 并入「通用 › 编辑体验」卡片 |
| 隐私锁 | 保留 | — |
| 版本与回收站 | 保留 | — |
| 备份与导出 | 保留 | 边界收窄为"把数据送出去 / 接回来" |
| 分享 | 保留 | — |
| MCP | 保留 | — |
| **数据管理** | **改名「附件」** | 只管附件占用、孤儿与清理（它本来就只管这些） |
| 实例管理 | 保留（仅 owner） | — |
| **关于** | **撤销** | 并入「通用」最底部 |

新顺序：**通用 / 账户与安全 / 隐私锁 / 版本与回收站 / 备份与导出 / 分享 / MCP / 附件 / 实例管理**（owner 10 / member 9）。

**为什么撤「编辑器」而不是撤「通用」**：「通用」的内容是"打开应用时看到什么"（启动视图、主题、树结构、筛选条），「编辑器」的内容是"打开一篇笔记时看到什么"（哪几档）。后者是前者的自然延伸，同属界面偏好，合在一页反而让"通用"更名副其实——它就是"通用界面偏好"。

**为什么「关于」进「通用」而不是进页头 ⓘ**：版本号与仓库地址是**低频查阅**内容，放在「通用」底部（需滚动才见）恰好匹配它的频次；放进 ⓘ 会让"我是哪个版本"变得不可见，而版本号在 bug 反馈里有实际用途。

### 2.2 作用域标识（本次最实质的修复）

「通用」与「编辑体验」里的每一行都标出作用域，**平铺可见，不进 ⓘ**：

| 设置项 | 作用域 | 徽标文案 |
|---|---|---|
| 主题 | 设备级 | `本机` |
| 启动视图 | 账号级 | `跟随账号` |
| 时区 | 账号级 | `跟随账号` |
| 待办筛选条 | 账号级 | `跟随账号` |
| 笔记本树结构 | 账号级 | `跟随账号` |
| 账户快捷菜单 | 账号级 | `跟随账号` |
| 编辑模式（`editor_modes`） | 账号级 | `跟随账号` |
| 编辑模式的"上次用的那一档" | 设备级 | `本机` |

**复用现有 `.badge`**（`app.css:4333`），不新造视觉语言。徽标对读屏 `aria-hidden`（同一信息已在可见文案与卡片 ⓘ 里，重复会污染可访问名）。

### 2.3 边界收窄

- **「备份与导出」**：只管"把数据送出去"（目标管理 / 推一次 / 导出 zip / 从备份恢复）。**不含**占用统计与清理。
- **「附件」**（原「数据管理」）：只管附件——概览、列表、孤儿清理。**不含**导出与恢复。

两者仍然不合并。理由：合并会让单页承载 7 张卡、超过 600 行，违背本次"降低单页体量方差"的目标；靠**改名字**（"数据管理"→"附件"）让承诺与内容一致，是更小的动作。

### 2.4 删掉页头噪音计数

`settings__count`（`SettingsPanel.tsx:258`）显示"共 N 个分类"。该数字对用户零信息量（左列看得见），且**随角色变化**（owner 10 / member 9），容易让人误以为漏了东西。

`DESIGN.md` §5.4-2 要求"实时计数保持可见"针对的是**有意义的状态**（回收站条目数、令牌数、附件数、进度），分类总数不属于这一类。回收站计数（`VersionsTrashPage.tsx:80`）等真实计数**全部保留**。

### 2.5 过期文案

| 位置 | 现文案 | 改为 |
|---|---|---|
| `SettingsPanel.tsx` 「已登录设备」 | 将在后续里程碑提供 | 尚未提供（改密是当前唯一能远程断开其他设备的办法，这句保留） |
| `InstancePage.tsx` 「成员账户管理」 | 会在 M6 提供 | 尚未提供（新增成员目前只能靠开放注册） |

两处都从"指向一个已经过去的里程碑"改成"如实陈述现状"。**不删占位行**——留着它用户才知道这个能力被考虑过。

## 四、验收点

1. 设置页左列 9 类（member）/ 10 类（owner），无「编辑器」「关于」。
2. 「通用」页内可完成：主题、启动视图、时区、筛选条、树结构、快捷菜单、编辑模式三档、版本号与仓库地址。
3. 每个设置行旁有可见的作用域徽标；`aria-hidden` 不污染可访问名。
4. 页头无"共 N 个分类"；回收站条目数等真实计数仍在。
5. `#/settings/editor` 与 `#/settings/about` 落到「通用」而非白屏或空页。
6. `pnpm lint` / `pnpm typecheck` / `pnpm test` 全绿。
7. 不新增生产依赖、不改接口、不改 `packages/shared` 契约。
