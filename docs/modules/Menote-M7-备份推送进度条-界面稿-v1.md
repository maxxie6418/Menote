## 一、为什么要一个弹窗，而不是就地展开

「推一次」点下去之后要做的事是**同一件、重复很多次**（每轮一批），用户在这段时间里不需要做任何选择，也看不到有别的信息在变。就地展开会把目标行撑高、让列表参差，而且**用户可能同时想去改别的目标**。

所以：**点「推一次」→ 弹窗跑循环 → 关掉**。弹窗只承担一件事：报告「推到哪了」。

## 二、一屏

```text
┌─ 推送到「家里的 NAS」 ─────────────── ✕ ─┐
│                                          │
│  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░  │
│  已推 120 / 340                          │
│                                          │
│  （结束后）推完了，340 个文件都已推到远端。│
│                                          │
│                    [ 关掉 ]              │
└──────────────────────────────────────────┘
```

### 块与取值

| 块 | 内容 | 取值来源 |
|---|---|---|
| 标题 | `推送到「{label}」` | 目标行 |
| **进度条** | `.pushbar` + `.pushbar__fill`，宽度 = `已推 / 总量` | 服务端 `total` 与 `remaining` |
| **数字行** | `已推 {done} / {total}` | 同上。**必须有数字**：DESIGN.md §3.2 第 4 条「语义色不得单独表意」，颜色只是辅助 |
| 结果行 | 三态文案（见下） | 循环的终态 |

**不铺说明性文字**。要解释的（为什么一轮只有一批、关掉会不会丢）进 `ⓘ` 或只在**非终态**时给一句。

## 三、四条落定的口径

### 1. 一轮就是一批，浏览器**循环**调用

服务端一轮推 ≤40 个（架构 §14.3 的外部子请求硬限额）。进度条是浏览器**反复调 `POST /api/backup/targets/:id/run`** 累出来的，不是服务端一口气推完。

**循环上限 50 轮**。到上限就停并如实说「这一轮推了 N 个，还剩 M 个没推完」——**不能让"用户一直在打字所以推不完"变成一个停不下来的循环**。

### 2. 中断续传**已经是状态机的性质**，界面只负责把它说清

游标在 D1（`user_backup_targets.cursor_seq`），**关掉页面、取消、关掉标签页都不丢进度**：下次点「推一次」从游标接着推。所以弹窗**允许随手关掉**（不设 `dismissable={false}`——那是不该让用户做的事），并且在**非终态关掉时**留一句「关掉也没关系，下次接着推」。

### 3. 三种终态要分开说

| 终态 | 文案 | 为什么不能混 |
|---|---|---|
| 推完 | `推完了，{total} 个文件都已推到远端。` | — |
| 到上限 / 用户中断 | `推了 {done} 个，还剩 {remaining} 个没推完。关掉也没关系，下次接着推。` | **这是常态不是出错**（一轮一批的硬限额下必然发生），说成"失败"会误导 |
| 出错 | `没推成：{error}`，**用 `banner--warn` 平铺** | 失败原因必须保持可见（DESIGN.md §5.4-2），不靠 Toast |

「这次没有需要推送的内容」是**第四种**：`pushed === 0 && remaining === 0`，说成「已经是最新的了」。

### 4. 视觉件：只用现有令牌，不自造一套

| 位置 | 取值 | 为什么 |
|---|---|---|
| 轨道底色 | `--panel-2` | 令牌表里它的用途就是"次级面板"；比 `--line` 更能看出"这是一条槽" |
| 填充 | `--primary-grad` | **现成令牌**，不必手拼 `linear-gradient`（DESIGN.md §3.2 第 2 条禁止硬编码渐变） |
| 圆角 | `--radius-sm`（6px） | 与胶囊同级；整条 6px 高、圆角 3px 才不显得两头尖 |
| 高度 | **6px** | 够看见、不抢注意力。`DESIGN.md` §5.2 的密度基调是「轻」 |

**深色主题自动成立**：两个都是令牌，切主题只改属性。

**`prefers-reduced-motion`**：填充**不做过渡动画**。理由是每轮循环只有几百毫秒到几秒，过渡动画既看不清又会在每轮重置一次——**动效只在解释空间关系时用**（DESIGN.md §6.3）。

## 四、这一轮不做

| 不做 | 理由 |
|---|---|
| **估剩余时间**（「约还要 30 秒」） | 远端速度差异极大，估出来必然不准，**不准的进度信息比没有更糟** |
| **点进度条暂停** | 暂停就是"不再循环调用"，关掉再点等价；不做一个假的控制 |
| **批量预览**（推之前列出会推哪些文件） | 这是另一件事、另一屏（要列文件名、要跨页），与「报告推到哪了」混在一起会让这一屏承担两件事。**真要做应单独立项**，不在这一轮 |
| **移动端** | `DESIGN.md` §2.4 仍未定稿；本稿按桌面稿实现但用弹性布局，不写"仅桌面成立"的东西 |
