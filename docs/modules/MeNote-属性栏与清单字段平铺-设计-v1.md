## §1 本轮要解决的问题

用户对「文章 YAML + 顶部属性栏」的期望是四条，实测后确认其中两条没做到，本轮一并修：

| # | 期望 | 改动前的实况 | 本稿 |
|---|---|---|---|
| 1 | 顶部属性块默认几项常用属性、**默认为空**，不设置就不写 YAML | 新增笔记**恒写** `title: 未命名笔记`；清空最后一个属性后会残留 `---\n\n---` 空围栏 | §8、§9 |
| 2 | 外部导入、本身已有 YAML（Obsidian 格式）的文章能读、能改，新增的属性兼容同一格式 | 已实现，但「+ 添加属性」只在**已有**外来键时才出现，空白笔记无处可加 | §6.4 |
| 3 | 属性块里新增的属性兼容 Obsidian 平铺格式 | 新增键走顶层平铺（兼容）；但**内置的清单三字段写在私有块 `menote.task:` 下**，Obsidian 侧看到的是一个对象而不是三个属性 | §3 |
| 4 | **YAML 不出现在正文编辑中** | 编辑器把整段 front matter 藏成**可点芯片**，芯片文字是顶层键名，点一下就在正文里展开原始 YAML | §7 |

## §2 新的 front matter 布局

```yaml
---
# —— 外来键：原样保留，位置在最前（既有约定，不动） ——
url: "https://…"
author:
  - "Unknown"

# —— MeNote 自有键：一律顶层、固定顺序 ——
title: 买菜            # 可缺省（见 §9）
tags: [生活, 购物]      # 可缺省
status: todo           # 可缺省，平铺（本稿新增）
due: 2026-09-30        # 可缺省，平铺（本稿新增）
priority: high         # 可缺省，平铺（本稿新增）

# —— 私有块：只在真有子键时才出现 ——
menote:
  type: table          # 表格键、converted_to 继续留在这里
---
```

**顺序规则**：外来键 → `title` → `tags` → `status` → `due` → `priority` → `menote:`。被 patch 命中的自有键**丢弃原位置、追加到自有键区末尾**（与 `title` / `tags` 今天的做法一致）；没命中的原样留在原位。

**`menote:` 块里只留 MeNote 私有且不便平铺的键**：`type` / `converted_to` / 表格的 `columns` / `views` / `row_id_column`。表格键**保持嵌套**（设计文档 §10.2 的口径不动）。

## §3 清单三字段平铺

### 3.1 键位

`status` / `due` / `priority` 从 `menote.task.*` 升为**顶层键**，取值口径不变（`tasks.ts:16-52`：`todo|doing|done`、`high|medium|low`、`YYYY-MM-DD`，并继续接受中文别名）。

`menote.task:` 这个键**不再写**；读到旧文档里的它按 §5 处理。

### 3.2 判定规则：键存在即清单条目（无条件接管）

`deriveTaskFields` 的判据由「`menote` 块里有没有 `task` 键」改为「**顶层 `status` / `due` / `priority` 里有没有键**」：

- 三个键一个都没有 → `isTask = false`（普通笔记）；
- 有任意一个 → `isTask = true`，值按老规则归一（不识别的值 → `null`，不抛错）。

**这是用户 2026-10-11 明确选的「无条件接管」**，代价见 §4。

### 3.3 写入规则

`MenotePatch.task` / `MenoteMeta.task` 的**类型与名字都不改**（仍是 `TaskFields | null`）——**改的只是键位**，两端调用点因此基本不用动形态。

- `patch.task = { status, due, priority }`：三个顶层键**整体重写**（丢弃原三个键后按固定顺序追加），值为空的键**不写行**；
- `patch.task = null`：删掉三个顶层键（= 去掉清单标记，语义与 M07-04 的「删 `task` 字段」等价）；
- `patch.task === undefined`：三个键一行不动。

**一条自然推论**：三个值都清空后没有任何键可写，条目**自动不再是清单条目**。

**但「属性块」不再提供回到这个状态的入口**（用户 2026-10-11 更正）：`STATUS_OPTIONS` 里的「未设为清单」项被删除（`ItemProps.tsx:56-61`），属性块只显示清单字段的**值**，不再承担「是否设为清单」这个开关。`patch.task = null` 的写入规则**保留**——清单侧动作仍可调用它，只是属性块不再是调用方。取消清单的入口等清单功能稳定后单独设计，见 §6.2 与 §12。

## §4 撞名与接管代价（无条件接管）

仓库里那份 Obsidian 真实样本（`packages/mdcore/test/frontmatter.test.ts` 的 `OB` 常量）顶层就有 `status: unread`。**无条件接管意味着这篇笔记会被认成清单条目**：

| 现象 | 说明 |
|---|---|
| 它出现在待办视图 | `items.is_task` 被派生为 1，首页待办预览收它（`features/home/model.ts:66`） |
| 属性块「状态」行显示为空 | `unread` 不是合法值 → 归一为 `null`；「其他属性」段里**也不会**再出现这一行（已被接管） |
| 一次属性块写入会覆盖掉 `unread` | 只有**属性块 / 清单动作**才会重写 front matter；改正文保存不会（保存的是编辑器全文） |

**代价已由用户确认接受**：顶层这三个键从此归 MeNote，`assertForeignKey` 的保留字集合加入它们（用户不能再把它们当普通属性新增）。

**一条缓解（本稿建议，实现时按最简做）**：属性块对被接管但值不识别的键，给一句**可见**的提示（如「`status: unread` 不是 MeNote 认识的值，改动这一行会覆盖它」）。理由是不让数据静默消失——这是「影响使用」而不是体验边角。不加新控件，就是一行文案。

### 4.1 与旧稿 §1.3 的关系

《笔记属性卡片》§1.3 写的是「**不把外来键映射成 MeNote 的字段**」，举的例子正是 `status: unread`。本稿是**收窄而非推翻**：除这三个顶层键外，其余外来键仍一律不映射、原样保留。该条需在旧稿里加一行指向本稿（见 §11）。

## §5 懒迁移（不写迁移脚本）

**读：双认。** 顶层三键与旧 `menote.task:` 都读得到结果——顶层优先，顶层没有才回落到 `menote.task`。

**写：只写平铺，并顺手删掉旧块。** 任何一次 `patch.task` 命中时，`menote.task:` 段整段移除，值改写为顶层三键。用户不改就原样留着，一改自动搬家。

**为什么不能批量改写存量**：隐私条目（`enc_self = 1`）的正文在服务端是密文，服务端读不到、改不了；批量迁移只能在前端全量拉取后重写，代价与风险都不成比例。这条与 `tags` 平铺（旧稿 §5.3）用的是同一套懒迁移理由。

**不需要数据库迁移**：`items.is_task` / `task_status` / `task_due` / `task_priority` 四个派生列的**列名与约束全不变**，只是派生源从旧块换成顶层键。0002 迁移与两个 `trg_items_task_flag_*` 触发器一行不动。

## §6 属性卡片的行为调整

### 6.1 常用属性保持现有四项

标签 / 状态 / 截止 / 优先级四行**都保留**（用户 2026-10-11 确认），控件形态照 `DESIGN.md` §5.3 的「条目属性 → 胶囊 chip」不变，不新增控件形态。其中「状态」与「优先级」两项的**内部取值**按 §6.2 / §6.3 调整。

### 6.2 状态不再承担「是否设为清单」

现状：`STATUS_OPTIONS` 是四项——待办 / 进行中 / 已完成 / **未设为清单**（`ItemProps.tsx:56-61`）。最后那项 `value: ""` 走的是 `onTaskChange(null)`，一次清掉三个键，**「是否设为清单」这件事完全由它承担**；第 55 行的注释写的也是「空 = 去掉清单标记」。

改为：**删掉这一项**（用户 2026-10-11 更正）。属性块只显示清单字段的值，不再提供「取消清单」的入口；「怎么取消清单」「清单条目算哪一类」留给清单功能稳定后单独设计。

**空态的显示**（体验边角，按 `AGENTS.md` 的最简原则办，不单独开一轮决策）：`status` 为空时渲染一个**只在此时出现**的占位项「未设置」。不这么做的话，一篇没有状态的笔记会被 `value=""` 落到第一项上、显示成「待办」——与 §6.3 要修的优先级「未设置显示成中」是同一类谎报。占位项只在当前值就是空的时候存在，所以**没有「从已设置回到空」的点击路径**，不会把删掉的开关从后门放回来。

### 6.3 优先级补「未设置」，默认全空

现状：`PRIORITY_OPTIONS` 只有高/中/低，`value = task?.priority ?? "medium"` → **未设置的笔记也显示「中」**，看起来像已设置。

改为：下拉里加「未设置」（= 该键不写行），未设置时 `value` 为空而不是 `medium`。同时**不再**在改动某一个字段时顺手补 `status: "todo"`——现状改一次优先级会把普通笔记变成清单条目（`ItemProps.tsx:318-326`），这不是「改一个属性」该有的副作用。

### 6.4 「其他属性」段常显，新增入口始终可用

现状：「其他属性」段与段内的「+ 添加属性」都只在 `foreign.length > 0` 时渲染（`ItemProps.tsx:338`、`:385-390`）→ **空白笔记根本没有新增入口**，与期望第 2 条直接冲突。

改为：「其他属性」段**始终渲染**；没有外来键时，段内只有一行「+ 添加属性」（可以视作空状态，不写「暂无」这类说明性文案——按 `AGENTS.md`，说明性文案进 `InfoHint`）。

### 6.5 删外来键补二次确认

现状：`ItemProps.tsx:375` 点了即删，与旧稿 §5.3 和 `DESIGN.md` §6.5 都不符。补确认框，文案照旧稿 §5.3 的三件事（删哪个键、删完 md 里就没有了、Obsidian 那边也看不到）。

### 6.6 键名与值的口径一律不动

键名原样显示、值按原格式写回、单行值含 `: ` 或 ` #` 时拒绝——旧稿 §3 / §4 / §7 全部继续有效。

## §7 编辑器不再显示 front matter

**取消「可点芯片 + 可展开」这条产品决定**（旧稿 §8.2 里写着「是否要默认永不显示是另一个产品决定，等看过效果再定」——现在定了：永不显示）。

做法：`apps/web/src/app/editor/frontmatter-hide.ts` 的 `Decoration.replace` **去掉 `FrontmatterChip` widget**，改为零宽替换；`frontmatterKeyNames` / `setRevealed` / `revealed` 状态一并删除，`apps/web/src/app/theme/app.css` 的 `.cm-fm-chip` 段删除。

**三条必须保住的不变量**（否则会出难查的 bug）：

1. **判据照旧**：第一行必须是 `---` 且必须能闭合；没闭合就**不隐藏**（用户可能正在写第一行）。
2. **光标不许钻进隐藏区**：`keepCursorOut` 保留（隐藏区不可见却可改是最糟的组合）。
3. **隐藏区是原子的**：`replace` 装饰天然把整段当原子单元，退格/删除在边界上要整段处理，不能只吃掉围栏而留下 `title: …` 裸露在正文里。这一条要有用例钉住。

**仍然不做「编辑器只存正文、保存时再贴回 front matter」**：标签、清单字段、标题都是菜单动作直接改 md 的，编辑器若持有 front matter 副本并每次回贴，会把那些刚写进去的改动抹回去（旧稿 §8.2 的结论继续有效）。

**副作用（要接受）**：正文编辑器里不再有任何查看/展开 YAML 的入口，属性卡片成为**唯一**入口。手上没有界面的 YAML（例如表格键）仍然看不见——但表格有自己的界面，清单字段有属性行，都不是问题。

## §8 清空最后一个属性不留空围栏（缺陷修复）

**现象（已实测复现）**：`updateMenoteKeys("---\ntags: [a]\n---\n\n正文", { tags: [] })` → `---\n\n---\n\n正文`；`updateMenoteKeys("---\ntitle: T\n---\n\n正文", { title: null })` 同样残留空壳。

**根因**：`frontmatter.ts:670` 的 `headLines` 为空时仍走拼围栏那条分支（`buildDocument` 在 `frontmatter.ts:550` 有 `head.length === 0` 的早返回，这里漏了）。

**修法**：`rendered.length === 0` 时直接返回 `split.body`（连带把围栏与它后面的空行一起收走）。

**配套用例**：清空 `tags` / 清空最后一个清单字段 / 删掉最后一个外来键，三条都必须回到「完全没有 front matter」的正文形态。

## §9 标题不再写进 md（推翻旧稿 §6）

**新口径**：新建笔记时**不写** `title:` 进 md；标题照旧存 `items.title` 派生列（`items.title NOT NULL` 的约束不变）。

这与旧稿 §6「`title` 进 md、md 为准」相反，是用户 2026-10-11 的选择：**不设置就不该有 YAML**。

| 场景 | 行为 |
|---|---|
| 新建笔记 / 新建表格 | **不写** `title:`（`useNoteCreation.ts:73-108`、`:180` 的那两处 `updateMenoteKeys(..., { title })` 去掉） |
| 在标题框改标题 | 只改 `items.title` 列，**不写** md |
| 导入一篇带 `title:` 的 md | 照读：`deriveTitle` 的 `present: true` 分支继续生效，属性块可以改它 |
| 导入的 `title:` 被改名后再保存 | 顶层 `title:` 仍在，跟着改（不改键位） |

**因此 `deriveTitle` 继续保留**（导入路径要用）；`DEFAULT_NOTE_TITLE` / `DEFAULT_TABLE_TITLE` 继续作为 `items.title` 的初值。

**旧稿 §6 的其余部分不受影响**：服务端仍不派生标题（隐私条目正文是密文，`frontmatter.ts:494-497` 的理由不变）。
