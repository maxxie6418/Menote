## 1. 现象与根因

### 1.1 标记在打字瞬间被反复隐藏（用户第 1 条的"写不出标题 + 闪动"）

判据链路：`revealAtOf`（`apps/web/src/app/editor/live-preview.ts:705-710`，有焦点且折叠光标时返回 `[head]`）→ `revealSpansFor`（`apps/web/src/app/editor/live-preview-reveal.ts:109-144`），命中判定是**半开区间**：

```
apps/web/src/app/editor/live-preview-reveal.ts:137
if (pos >= span.from && pos < span.to)
```

刚敲完 `##` 时光标停在标记的 `to` 上，`pos === to` **不算命中**。于是每次重算都把这一段标记换成零宽 `Decoration.replace`（`live-preview.ts:281-293`，标题分支 `:335`/`:392`），而重算的触发时机是"停手 90ms"（`live-preview.ts:517` 的 `REBUILD_IDLE_MS`，`:578-582` 排期）。表现就是：敲完 `#` 稍一停顿，`#` 被藏起来、该行按 `.cm-live-h1/h2` 渲染（字号与行高逐级切换、可见文字左右位移），你再敲第二个 `#` 又变回去——用户看到的"快速闪动"，以及"根本看不见自己打的 `#`"。

`live-preview.ts:510-517` 那段注释写着"新敲出来的标记在语法树里还不存在，本来就该以源码示人"——**这半句与事实不符**：CodeMirror 的增量解析在一次改动之后就会把改动行重新解析，`syntaxTree(state)` 里已经有新标记了，所以重算一定会把它当标记藏起来。该注释需在本次落码时订正。

### 1.2 往上拖选时选区被塌成光标（用户第 1 条的"无法划选文字"）

`frontmatter-hide.ts:104-116`：

```
frontmatter-hide.ts:111
const inside = selection.ranges.some((one) => one.from < range.to && one.to > range.from);
frontmatter-hide.ts:115
update.view.dispatch({ selection: { anchor: range.to, head: range.to }, scrollIntoView: false });
```

只要选区**与隐藏的 front matter 相交**，整个选区就被换成隐藏区末尾的一个光标——`anchor` 与 `head` 一起丢，用户手里正在拖的那段选择消失，只剩一个光标在动，正是"拖拽变成直接拖动光标位置"。文件头 `:46` 写的意图是"选区落进去就**顶到隐藏区末尾**"，实现却做成了整段塌陷：**代码比注释更狠**。

触发场景很常见：文档有属性（属性都在 front matter 里、且整段零宽隐藏）时，从正文往上拖到顶，鼠标划过隐藏区上方，`posAtCoords` 给出的位置落进隐藏区 → 塌陷。

> 这一条与 1.3 都需要真机复现确认（本稿的两条推断都有源码依据，但没有浏览器实测；见 §6 的"复现优先"）。

### 1.3 纸面留白点了不落光标（用户第 6 条）

CodeMirror 只把鼠标事件绑在 `view.contentDOM`（即 `.cm-content`）上；而纸面是 `.cm-scroller`（`app.css:838-845`，`max-width:800px`、`padding: var(--sp-5) 48px 80px`、`min-height: calc(800px * 297 / 210)`），左右各 48px 内边距与文字下方的空白都在 `.cm-content` 之外，点击不产生任何响应。高度百分比链又断了两处：`theme.ts:24` 的 `"&": { height: "100%" }` 之上，`[data-editor]` 只有 `min-height:100%`、再上一层是无样式 div（auto），所以 100% 算成 auto，`.cm-content{min-height:100%}` 也一并失效。用户描述"只有点第一排才出现编辑光标"，就是文字只占第一排时唯一能点的只有那一排。

### 1.4 当前行底色太醒目（用户第 6 条后半）

`app.css:881-888`：`.cm-activeLine{background:transparent}`、`.cm-focused .cm-activeLine{background:var(--bg-soft)}`。纸面是 `--panel`（`tokens.css:23`，浅 `#ffffff` / 深 `#242424`），当前行是 `--bg-soft`（`tokens.css:22`，浅 `#f7f7f7` / 深 `#1e1e1e`）。**换令牌救不了**：比 `--bg-soft` 更淡的中性令牌不存在（`--panel-2` 是 `#f2f2f2`，更深）。取法见 §4.2。

### 1.5 附件按钮的位置（用户第 5 条）

`NoteWorkspace.tsx:393` 是 `.docpane__head`；`:406-442` 是隐藏 `<input type="file" multiple>`（`:417-431`）与「添加附件」按钮（`:432-440`），紧挨着 `:451-467` 的三档模式切换条；格式工具栏在 `:513` 才按 `!isTable && !bodyLocked && (edit|live)` 渲染。工具栏的插入组在 `EditorToolbar.tsx:51-54`（现为链接、代码块）。

## 2. 需求 1.1：给"正在编辑的那一行"加冻结

### 2.1 口径（用户 2026-10-18 的选择）

**不改判据，只改重算时机**：光标停在某一行期间，那一行的呈现**保持它被进入时的样子**；光标离开该行（或该行的显现结论发生变化）才重新渲染。用户接受的代价是"正在编辑的那一行渲染会迟一步"——这正是本稿要的东西。

与 v0.8.37 那条口径的关系：**"光标进标记才显现源码"原样保留**——用方向键把光标移进已有 `## ` 内部，显现结论变化 → 立即解锁并显现源码；而"点一下某行就把整行源码摊开"（v0.8.36 的旧口径）**没有**被请回来。

### 2.2 机制

设 `L` = 光标所在行号，`R` = 该行按现行判据（`revealSpansFor`，半开区间）**应显现**的标记区间集合。两者都随文档变更做位置映射（`map`），与装饰同步。

- **冻结**：一次重算发生时，若 `{L, R}` 与上次锁定的 `{L₀, R₀}` 一致 → 该行范围内**丢弃新算出的装饰，改用锁定那一份**；其余行照常重算。
- **解锁**：`L ≠ L₀`、或 `R ≠ R₀`、或本次改动里有**跨行**变更（含粘贴多行、回车换行）→ 该行按新结果渲染，并以新 `{L, R}` 重新加锁。
- **冻结的范围**：只覆盖 `live-preview` 自己的装饰（标记隐藏、`.cm-live-h*` 行类名、清单复选框、图片内联等）。**代码高亮的 token 装饰不参与冻结**——它由 `codeMarks` 独立产出，必须永远跟着内容走，否则在代码块里打字会出现"这一行没上色、旁边上色"的怪相。落码时这条按**装饰类型**实现：只有 **point 装饰**（`Decoration.replace` / `Decoration.line`）进冻结集，`Decoration.mark` 一律现场重算（`live-preview-lock.ts` 的 `isFreezable`）。**首版没有这个过滤，真机一测就现原形**（§6.1-C），所以它是一个"设计稿写了、实现第一版漏了"的坑，不是边角取舍。
- 冻结不改变"每次改动仍要走一遍重算"这件事，只改变**这一行**的产出。这样即使后台 ParseWorker 推进语法树（`live-preview.ts:583-587` 的树引用分支）触发了重算，这一行**照样冻结**，闪烁不会从这条路绕回来。

**为什么这样能同时治好两个症状**：敲第一个 `#` 时 `R = ∅`（光标在 `to`，半开判据不命中），敲完第二个 `#` 时 `R` 仍是 `∅` → 一直冻结 → 新敲进去的字符**没有任何标记装饰**，以源码示人、看得见也不闪；光标移到别的行 → 解锁 → 这一行立即按标题渲染。

### 2.3 落点与文件预算

- 新增纯函数模块 `apps/web/src/app/editor/live-preview-lock.ts`：按行切装饰（`sliceLine`）、显现集合比较（`equalsReveal`）、冻结替换（`freezeLine`）、以及"是否需要解锁"的判定。**必须是纯函数**，因为 jsdom 里建不出真的 `EditorView`（`frontmatter-hide.ts:26-30` 记过这个坑：纯函数测得再全，也不代表扩展真能挂上）。
- `live-preview.ts` 只增加接线（约 10-15 行）：`update()` 里维护锁定状态、`rebuild()` 里应用冻结。该文件已 723 行，超预算的部分**不往这里堆**。
- 订正 `live-preview.ts:510-517` 那段与事实不符的注释，并在 `:523-535` 的"重算时机"表里补两行（冻结规则、解锁条件）。

## 3. 需求 1.2：选区不许被整段塌掉

把 `keepCursorOut`（`frontmatter-hide.ts:104-116`）从"塌成光标"改成"**只夹落在隐藏区里的那一端**"：

- 对每个 range：`from` 落进隐藏区 → 夹到 `range.to`（隐藏区末尾）；`head` 落进隐藏区 → 同样夹到 `range.to`。两端都在隐藏区里（整段选区都在其中）→ 退成 `range.to` 处的光标（保持原行为）。
- 夹完与当前选区**相同就不派发**（保留原 `:113` 的自激保护）。
- 多光标用 `EditorSelection.create` 一次性重建，不要逐个 `dispatch`。

效果：从正文往上拖到顶，选区停在隐藏区之后（正文第一行行首），用户手里那段选择**保住**；隐藏区仍然不可编辑、边界退格仍然整段处理（`atomicRanges` 不动）。

## 4. 需求 1.3 / 1.4：点击落点与当前行

### 4.1 让纸面整块可点（先走 CSS，不给编辑器加第二套鼠标处理）

两处改动，都在 `app.css`：

1. **内边距从纸面搬到正文元素**：`padding: var(--sp-5) 48px 80px` 由 `[data-editor] .cm-scroller`（`app.css:838-845`）移到 `[data-editor] .cm-content`（`:846-856`）。`.cm-content` 是 CodeMirror 自己的 `contentDOM`，**点它的内边距会落到 CM 的 mousedown 上**，由 `posAtCoords` 取最近位置落光标，左右留白因此一次解决。搬完要显式补 `width:100%; box-sizing:border-box;`，否则内容盒宽度会变成 800+96 把横向滚动条顶出来。视觉零变化（纸面 800、文字列 704 都不变）。
2. **让正文元素铺满纸面高度**：给 `[data-editor] .cm-scroller` 加 `align-items: stretch`（覆盖 CodeMirror 自带的 `align-items: flex-start !important`）。这样 `.cm-content` 会被拉到纸面的 A4 最小高度，文字下方的空白也归它，点那里同样落光标。`.cm-gutters` 跟着 stretch 无副作用（背景本来就是透明）。

**兜底方案（只在实测发现 CM 版本行为不一致时才用）**：在宿主 div（`Editor.tsx:416-422`）上补一个 `mousedown` 兜底——`event.target` 不在 `contentDOM` 内时用 `view.posAtCoords` 取最近位置并 dispatch + focus。它不需要改 CM 的样式约定，但引入了第二处鼠标处理，**默认不用**。

### 4.2 当前行不要那么醒目

整行底色**去掉**（`.cm-focused .cm-activeLine` 的 `background` 不再给 `--bg-soft`），只保留光标与行号栏的当前行标记（`highlightActiveLineGutter` 仍只在有行号的档存在，`Editor.tsx:436-441` 不动）。理由：想变淡只能换令牌，而 `--bg-soft` 已经是白纸/深纸上最淡的一档中性色；保留"整行被裹一层色"的形态就一定显眼，而用户要的是"不要太独特"。这一条属体验边角，按最简处理，用起来还觉得缺再补（AGENTS.md「可有可无的体验项按最简原则处理」）。
