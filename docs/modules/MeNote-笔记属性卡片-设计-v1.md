## §1 目标与范围

### 1.1 要解决的问题

v0.8.10 把 front matter 在编辑器里藏成了一个可点的小标签之后，属性**没有正式的查看与编辑入口**：

| 属性 | 藏起来之前 | 藏起来之后 |
|---|---|---|
| 标题 | 有独立输入框 | 不变 ✓ |
| **标签** | 只能正文打 `#标签` 或手改 YAML | **同左，且 YAML 收进小标签后面，从 1 次点击变 2 次** |
| **清单字段** | 只能在待办视图的侧滑详情里改 | 同左（笔记正文区本来就进不去） |

标签**至今没有任何界面**——mdcore 早就有 `updateMenoteKeys(body, {tags})`，但界面上没有任何地方调它。

### 1.2 两条已定的口径（用户 2026-10-04）

1. **键名原样显示**，不做任何方向的翻译：英文不译成中文，中文不改写成英文。理由见 §3。
2. **外来键给删除入口**——「绝对编辑权由用户掌握」。理由与代价见 §5。

### 1.3 不做

- **不引入通用 YAML 库**（§4 解释了为什么不需要）。
- **不把外来键映射成 MeNote 的字段**。`status: unread` 在某个 Obsidian 插件里是阅读态，换个插件可能指别的东西；猜错比不猜更糟。这与 v0.8.10「顶层 `type` 刻意不认、留给外来」是同一条理由。
- **不删 `title` / `tags` / `menote`**（§5）。
- **不动 `wiki/`**。本稿是实现层的显示口径，不引入新数据模型。

## §2 卡片结构

放在**标题输入框之下、正文之上**，与标题同属正文区顶部一带。

```
标题输入框（既有，不动）
┌─ 属性 ──────────────────────────────┐
│ 标签      [claude ×] [tooling ×] [+ 添加] │
│ 状态      [待办 ▾]                        │
│ 截止      [2026-10-08]                    │
│ 优先级    [中 ▾]                          │
├─ 其他属性 · 原样保留 ───────────────────┤
│ url       [https://x.com/…        ] [×] │
│ author    [- "Unknown"              ] [×] │   ← 块序列用多行框
│ captured  [2026-03-25              ] [×] │
│ like      [false                   ] [×] │
│ comment   [（空）                  ] [×] │
│ status    [unread                  ] [×] │
│ [+ 添加属性]                              │
└──────────────────────────────────────┘
正文
```

### 2.1 三条结构决定

1. **标题不进卡片。** 它已有独立输入框；放两份就是两处真相。
2. **形态照 DESIGN.md §5.3 已定的那一行**：「条目属性（标签、截止、优先级、状态）→ 胶囊 `chip`」。复用现成的 `Chip`（`variant="tag"`），不新造控件。
3. **「其他属性」单独一段、底色略深**，和上面 MeNote 自己的键分区隔——用户一眼能看出「这堆是外部工具写的」。

### 2.2 清单字段始终显示

不是「仅清单条目才显示」。普通笔记在「状态」里选一项就是**把它设为清单**（这正是 M07 的判定：有没有 `menote.task` 键）。藏起来等于没有入口。

### 2.3 空状态

- 没有标签：只显示「+ 添加」。
- 没有任何外来键：这一段不显示（不是显示一个空壳）。
- Memo 不出现这张卡片（`NoteWorkspace` 只服务 note / table；且 Memo 的 `items.title` 必须为 null）。

## §3 键名口径：原样

**显示的就是键名本身**（等宽字体），不配中文标签。

理由：`url` / `author` / `captured` / `like` / `comment` / `status` 这些键**不是标准**，是某个 Obsidian 插件写的。同一个 `status` 在别的插件里可能指流程状态。贴上「状态」两个字之后，用户看到一个叫「状态」的东西写着 `unread`，会以为 MeNote 懂它——而它可能不懂。

用户写 `url` 时知道它是什么；需要时 Obsidian 插件自己的界面会显示同样的键。**键名保持原样，是把解释权留给写它的那个人。**

## §4 外来键的读写：按原格式

### 4.1 做法

**不把值解析成结构再拼回去。** 那才是真的要引 YAML 库，也是 `frontmatter.ts` 文件头明确不做的事。

实际做法：只**认出这个键占哪几行**（`splitSegments` 已经能给出顶格键 + 其缩进子行），然后把用户写的原文**按原样写回同一位置**。

### 4.2 形状保留

| 原形状 | 写回 |
|---|---|
| `key: value`（一行） | 仍是 `key: value` |
| `key:` + 缩进子行（块序列） | 仍是 `key:` + 缩进子行 |

所以 `author:` 下面带 `- "Unknown"` 的，界面上就给多行框；引号、空格、缩进都是用户说了算。

### 4.3 新键默认单行

新加的键默认写成 `key: value`。需要块序列时用户自己在值里换行（前一行留空即可）。

## §5 删除语义

**给删除**（用户明确要求：绝对编辑权归用户）。

### 5.1 能删什么

| 键 | 能否删 | 怎么清空 |
|---|---|---|
| 外来键（`url` / `author` / …） | **能**，每行末尾一个 × | 删键 = 整行移除；清空值 = 把输入框清空 |
| `tags` | 不能删键 | 点某个 chip 的 × 删单个；清空输入 = 删全部 |
| `title` | 不能删键 | 它有自己的输入框 |
| `menote` | **不能** | 表格结构在那儿，删了等于毁数据 |

### 5.2 为什么要拦三个

`title` / `tags` 在上面已有专门的行——给它们第二条删除路径就是同一个值两处真相。`menote` 块是表格的列定义、视图、行 ID 列，删掉不是「少个属性」而是「这张表没了」。

### 5.3 破坏性确认

删外来键**要确认**（DESIGN.md §6.5：破坏性操作必须二次确认），确认框写明三件事：删哪个键、删完 md 里就没有了、**Obsidian 那边也会看不到**。虽然版本历史能撤回，但撤回要走版本面板，不是顺手能做的——所以值得点一下确认。

## §6 写入链路：必须走编辑器，不能走 `saveDraft`

**这是本设计最容易做错、也最要紧的一条。**

### 6.1 问题

标签 / 清单字段 / 外来键都存在 md 里，而**编辑器持有正文的一份文本**。如果卡片直接 `saveDraft(itemId, 新md)`：

1. 卡片写入新 md（带新标签）；
2. 编辑器那份文本**还是旧的**（没有新标签）；
3. 用户接着敲一个字 → `onInput(旧文本 + 一个字)` → 自动保存把**新标签覆盖掉**。

标签静默消失。用户在界面上看着标签还在，刷新一下就没了。

### 6.2 做法：走 `editorHandle`

照仓库既有先例——移除附件引用就是这么做的（`app/workarea/NotesPane.tsx:100`）：

> 真正的删改走 `editorHandle.replace`：视图、光标与保存链路都照常，弹窗只管列与收指令。

所以卡片算出新 md 之后，**不自己存**，而是把 front matter 的改动推进编辑器：

```
卡片算新 md（纯函数，mdcore）
  → editorHandle.replaceFrontmatter(旧 front matter 文本, 新 front matter 文本)
  → 编辑器文本变了 → onChange → handleInput → previewSource
  → 编辑器既有的自动保存落草稿、入队 body   ✓ 一条路，不打架
```

派生列（`items.tags` / 任务三列）另走 `enqueueMetaPatch`——那是**列**的通道，与正文通道各管各的，本来就是两回事。

### 6.3 `replaceFrontmatter` 为什么要新加一个方法

现有的 `EditorHandle.replace(marker, text)` **找不到标记时会退化成在光标处插入**（`Editor.tsx:401-404`，那是为附件占位设计的兜底）。对属性卡片那是灾难：把整段 front matter 插到正文中间。

所以句柄上加一个**只认文档开头、找不到就什么都不做并返回 `false`** 的方法：

```ts
replaceFrontmatter(expected: string, next: string): boolean
```

- 只在 `doc.startsWith(expected)` 时替换 `[0, expected.length]`；
- 否则**不做任何事**、返回 `false`（界面据此提示「正文已变，请重试」）。

### 6.4 派生列的写入

`items.tags` / 任务三列**只更新列 + 入队 meta patch，不碰草稿**——草稿由编辑器那条路负责。两条路各写各的字段，不会互相覆盖。

## §7 校验与降级

| 情况 | 处置 |
|---|---|
| 键名含 `:` 或空格 | **拒绝**并说明原因（含冒号或空格的键写进去会让整块 YAML 坏掉） |
| 键名撞 `title` / `tags` / `menote` | 拒绝，指向上面已有的行 |
| 单行值里含 `: ` 或 ` #` | **拒绝**并说明（YAML 纯量里这两个会截断）。需要就自己加引号——我们不自动加，因为「按原格式」意味着不改用户写的字 |
| 键名重复 | 拒绝 |
| front matter 没闭合（用户正在写第一行） | 卡片**不显示属性区**（此时任何改写都不可靠） |
| 预览档（无可编辑编辑器） | 卡片**只读**并说明「切到「仅编辑」才能改属性」（DESIGN.md §6.1：禁用必须给原因） |

## §9 风险

| 风险 | 缓解 |
|---|---|
| 卡片改 md 后编辑器没跟上，标签被下一次自动保存覆盖 | §6——走 `editorHandle`，不自己存草稿；用例钉住「写完标签再敲一个字，标签还在」 |
| `replaceFrontmatter` 找不到就插入 | 新方法不做退化，返回 `false` 并提示 |
| 单行值里写了 `: ` 产出非法 YAML | 写前拒绝并说明（§7） |
| 表格条目的 `menote:` 块被误删 | `menote` 不给删除入口（§5.1） |
| 卡片在 `NoteWorkspace` 里顶破 500 行预算 | 卡片是独立组件文件（`features/notes/ui/ItemProps.tsx`），`NoteWorkspace` 只多几行接线 |
