## 零、三个已定决策（用户 2026-10-04）

| 问题 | 决定 |
|---|---|
| 「页面」指什么 | **就是笔记与表格（条目）**。条目早能收藏，缺的只是首页入口 |
| 收藏文件夹怎么存 | **给 `folders` 加 `starred` 字段，走全链路**（不用「塞进用户设置」那条省事路子） |
| 作用范围 | **随账号同步**，与现有 `items.starred` 同口径 |

**为什么第三问的答案是「同口径」而不是「各自一份」**：`items.starred` 已经是随账号同步的，收藏文件夹另起一套机制只会制造两种收藏。代价是**同一账号的家人看到彼此收藏的文件夹**——这是既有收藏本来就有的性质，不是新引入的。已如实登记，见 §六。

## 二、功能定义

**快捷收藏**：首页上一个区块，把「我收藏过的东西」集中放在一处。

```
快捷收藏
  文件夹   [学习] [生活] [工作]          ← 收藏的文件夹（chip，新能力）
  笔记表格 交物业费         10月4日       ← 收藏的条目（列表行，已有能力）
          家庭预算         10月3日
```

| 点 | 口径 |
|---|---|
| **为什么不是「再建一个收藏列表」** | 功能栏已经有「收藏」视图（列 starred 条目），首页再列一遍**同一个集合**。本区块的价值是**两件事合到一处**：文件夹收藏**没有任何视图能列**（必须新做），条目收藏则是「不用跳过去就知道自己收藏了什么」 |
| **一个区，不是两个** | 文件夹与条目同属「我的收藏」，**同块呈现**（文件夹一行 chip、条目若干行），不拆成两个带标题的区块——否则又是卡片墙 |
| **上限** | 文件夹全列；条目**最多 5 条**，按最近收藏时间倒序，块尾给「查看全部 N 条 → 收藏视图」出口。理由：快捷区要的是「一眼够到」，不是「在这里读完」 |
| **空态** | 一个都没收藏时不渲染整块（不留空标题）。收藏了文件夹没收藏条目时，条目那行不出现；反之亦然 |
| **不新增主操作** | 整块只有「跳转」与「取消收藏」两个弱操作（DESIGN.md §5.1：每个区域最多一个主操作） |

## 三、界面（用四层模块拼，不新造外观）

| 元素 | 用哪一层 | 怎么长 |
|---|---|---|
| 区块标题「快捷收藏」 | L1 `.t-section` | 与其它区块同一写法 |
| 收藏的文件夹 | L3 `.chip` | 与快速导航同一颗胶囊，**只是内容由收藏驱动** |
| 收藏的条目 | L4 `.row` | 主文本 + 日期，`.rows` 管行间分隔线 |
| 「查看全部 →」 | L3 `.btn--ghost` | 弱操作 |

**这一块不引入任何新外观**——这就是模块化的意义：新增一个区**不需要新增一条 CSS 规则**，只是拿既有基件换内容。这也是它与上一版 `.home-acts-bar` 那种「每块自己一套」的根本差别。

**位置**：放在**快捷方式按钮行之后、快速导航 chip 组之前**。理由是这三段构成一条自然的漏斗——「做什么（按钮）→ 我常去的（快捷收藏）→ 全部（导航）」。

**收藏入口**（两处，都要能加也能取消）：
1. 文件夹树每一行的「更多」菜单 → 「收藏 / 取消收藏」
2. 条目的更多菜单**已有**「收藏 / 取消收藏」（M04-08），不动

**加密空间**：那个 `is_enc_space = 1` 的内置节点**不提供收藏**——它是内置记录不是普通文件夹，收藏它没有任何意义。空间内的普通文件夹**可以**收藏（与条目同口径）。

## 四、数据模型改动（这一节是本轮的主体与风险所在）

### 4.1 D1 迁移 `0009_folders_starred.ts`

```sql
ALTER TABLE folders ADD COLUMN starred INTEGER NOT NULL DEFAULT 0;
```

`DEFAULT 0` 同时完成回填：现有文件夹一律「未收藏」，不需要单独 UPDATE。

### 4.2 ⚠️ 部署窗口：这条不做对会直接让同步失败

**这是本设计最容易翻车的地方，必须写清。**

同步响应是用 `v.safeParse(SyncResponseSchema, …)` 校验的，而 `packages/shared/test/protocol.test.ts:86` 已经钉住了一条：**缺字段 = 整份响应校验失败**（那里删掉 `content_hash` 就断言 false）。

于是如果 `FolderMetaSchema` 把 `starred` 写成**必填**：

> 部署窗口里（新客户端已更新、Worker 还没更新 / 迁移还没跑），
> 旧 Worker 返回的 folders **没有 starred** → `safeParse` 失败 → **整个同步挂掉**，
> 表现是「首页数据全空」而不是「少一个收藏标记」。

**正确做法：照仓库既有的两处先例**——`sync.ts` 里的 `tombstones` 与 `settings` 都是 `v.optional(…, 默认值)`，注释里写明「部署窗口里旧 Worker 的响应没有这个字段时，新客户端不该因此失败」。

```
FolderMetaSchema.starred: v.optional(FlagSchema, 0)
```

服务端一旦迁移完、开始回传 `starred`，客户端自然就用真值；迁移前一律按 0 处理。**这个 optional 要保留，不要在「迁移都跑完了」之后清理**——清理那一刻正好是下一次部署窗口的起点。

**反向**（旧客户端 + 新 Worker）也要验：新 Worker 多返回的 `starred` 键，旧客户端的 valibot 是**忽略未知键**还是**报错**？本稿未查实，落地时**必须验一次**（用旧版契约去 safeParse 一条带 starred 的 folders）。若报错，则服务端要多等一个版本再回传该列。

### 4.3 共享契约

`FolderMetaSchema` 加 `starred`（optional + 默认 0，见上）。`FolderWriteMeta` 若有白名单式定义，同步加。

### 4.4 本地库

`apps/web/src/data/db/schema.ts`：`version(8)`，`folders` 的索引串加上 `starred`。
纯新增字段，Dexie **不需要 upgrade 迁移数据**（旧行读出来 `starred` 是 `undefined`，由读取处归一化成 0）。

### 4.5 同步与落库

| 环节 | 改动 |
|---|---|
| 客户端 push | `data/sync/push.ts`：`create_folder` / `patch_folder` 的 payload 带 `starred`（`items` 那边已有先例，见 `push.ts:242`） |
| 服务端写 | `services/folders.ts`：`patchFolder` 的白名单加 `starred`（现只有 name / parent_id 等，`services/folders.ts:169`） |
| 服务端读 | 迁移生效后 `SELECT *` 自然带回，无需改查询 |
| 冲突 | 沿用 `meta_rev` 乐观锁，**不生成冲突副本**（与文件夹改名/移动同口径，拆解 M13-04） |

## 七、明确不做

| 不做 | 理由 |
|---|---|
| 修「文件夹不进备份」这个既有缺口 | 与本需求无关，且是**删除风险级**的问题，不该顺手改。**如实登记**：备份还原后文件夹结构会丢（条目仍在，`folder_id` 指向不存在的文件夹）——需要单独一轮处理 |
| 扩 MCP 工具 | 收藏文件夹是个人导航偏好，不是内容操作；且既有口径就是「文件夹树不进 MCP」 |
| 给 Memo 加收藏 | Q8 已定：收藏视图不含 Memo，加了没有可见结果 |
| 「收藏夹」可排序 / 可拖拽 | 需求没写。要排顺序再说 |
| 收藏文件夹的批量操作 | 同上 |
