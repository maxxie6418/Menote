一、这次改的是「分层」，不是某一块好不好看

上一版的问题是每块自己长成自己的样子：统计一条带、动态一张卡、动作一块壳。 于是页面看起来像四件不同的东西拼的。这里先定四层基础件，每类只有一种长相， 首页只用它们拼 —— 换句话说，.home-card / .home-band / .home-acts-bar 这类「每块自己一套」的类名不再存在。

L1 排版.t-data / .t-section / .t-body / .t-meta / .t-label

按角色取样式，不按字号取。数据拿全系统最大的字号，标签拿最小的 —— 数字是内容不是装饰，这是「数据要是数据的样式」的第一句。

L2 容器.card / .card--bare / .sec

卡片只有一种长相（面板底 + 1px 描边 + 10px 圆角 + 16px 内边距）。 副内容用 --bare 把框去掉，靠位置和留白表示次要 —— 不发明「另一种边框」。

L3 控件.btn / .btn--primary / .btn--ghost / .chip

按钮就是按钮：31px 高、8px 内边距、6px 圆角，三档只换令牌不换几何。 全屏最多一个 --primary（DESIGN.md §5.1）。

L4 重复单元.stat / .stat-row / .row / .rows

数据对与列表行各一份定义，首页、待办、搜索结果共用。行与行之间一条 1px 分隔线， 不再靠「卡片里的一堆裸文字」制造节奏。

四、这套分层的落地代价（先说清，别到时候 surprise）

  • 要动的不止首页。`.card` / `.btn` / `.row` / `.stat` 一旦是全站基件， 别的屏（待办、Memo、设置、笔记列表）要逐个换成基件类，否则「基件」只是首页的基件。 建议分两批：先落基件 + 只改首页（本稿范围），下一批再迁移别的屏。
  • 类名从「按块」变成「按角色」。.home-card--lead、.home-band、 .home-acts-bar 这类要删掉，改为 .card / .card--bare / .acts。 好消息是首页三个组件（今日待办 / 最近动态 / 快捷方式）反而变简单了 —— 壳不再各写各的。
  • 主次不再靠装饰：上一版给焦点卡加的橙色左边条在分层下没必要 —— 页面里只有一张卡片，主次已经由「有框 / 无框」说清。装饰越少越不容易看腻。
  • 这一稿的数据没变：还是笔记 / 表格 / Memo 三个数字、还是照全量口径、锁定三态照旧。 只改「怎么摆、怎么分层」。
需要你拍板的两处：① 统计是留在内容顶部做数据带（本稿做法），还是回到页头右侧； ② 焦点卡保留纯白卡片（本稿做法），还是加深一层底色做强调。
